# 🔒 安全政策 / Security Policy

## 报告漏洞

如果你发现了安全漏洞（比如远程代码执行、敏感信息泄漏、依赖漏洞），请**不要**公开开 Issue。

请通过 GitHub 仓库的 **Security → Report a vulnerability** 功能私下报告，或直接发邮件给维护者（在 GitHub 个人主页可见）。

收到后我们会在 **7 天内**回复确认，并尽快发布修复。

## 本项目已采取的安全措施

- 🔑 **密钥不入库**：`.gitignore` 排除了所有可能的密钥/模型缓存文件。
- 🏷️ **提交历史净化**：开发过程中清除了提交历史里的个人邮箱，改用 GitHub noreply 邮箱。
- 🔒 **纯本地运行**：图片只在本地处理，不上传任何第三方服务。
- 📄 **明文凭据零容忍**：仓库任何文件都不得出现 API Key、密码、token、个人邮箱。

## 给用户的安全建议

- 不要把 API Key 写进聊天记录或截图发给任何人。
- 不要把密码通过聊天工具发送——这等于公开。
- 给 Claude Code 配置权限白名单，而不是全程 `--dangerously-skip-permissions`。
- 定期检查你 GitHub 账号的已授权应用，及时撤销不用的。

## 支持的版本

| 版本 | 支持 |
|---|---|
| master / 最新版 | ✅ 支持 |
| 旧 tag | ❌ 不主动维护 |

## 提交敏感信息的补救

如果不小心把密钥推上了 Git 历史：
1. **立即轮换**该密钥（在对应平台重新生成）。
2. 重写 git 历史移除该信息（参考本项目 `docs/TROUBLESHOOTING.md` 或 `git filter-branch` / `git filter-repo`）。
3. 强制推送覆盖远端。
4. 在安全公告渠道说明影响范围。

> 记住：**推上 GitHub 的密钥，即使删了也可能已被抓取。轮换是唯一可靠的补救。**
